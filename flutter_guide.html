What is Flutter?

Flutter is a toolkit from Google for building apps for iOS, Android, web, and desktop — all from a single codebase written in a language called Dart.

Instead of writing one app for iPhone and another for Android, you write it once. Flutter draws every pixel on the screen itself, so your app looks and behaves the same everywhere.

🎯One codebase

Write once, ship to many platforms.

⚡Hot reload

Change code and see it instantly without restarting the app.

🧱Widget-based

Your entire UI is built from small composable pieces called widgets.

🎨Pixel control

Beautiful, custom designs that look identical on every device.

💡

The golden rule: In Flutter, everything is a widget — text, buttons, padding, even the whole app. Remember this and the rest clicks into place.

Anatomy of a Flutter App

Every Flutter app starts from a single entry point: the main() function. It calls runApp() and hands it the root widget of your app.

main.dart
import 'package:flutter/material.dart';

void main() {
  // This is where the app begins.
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'My First App',
      home: HomePage(),   // the first screen
    );
  }
}

A few things to notice:

  • MaterialApp wraps your whole app and provides theming, navigation, and more.
  • The build() method returns the UI. Flutter calls it to figure out what to draw.
  • BuildContext is a handle to where this widget lives in the tree — you'll use it a lot.

The Scaffold

A Scaffold gives you the basic visual skeleton of a screen — an app bar at the top, a body in the middle, and optional floating buttons or bottom bars.

Think of it as the blank page layout that every typical screen starts from.

home_page.dart
class HomePage extends StatelessWidget {
  const HomePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Home'),
      ),
      body: const Center(
        child: Text('Hello, Flutter! 👋'),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {},
        child: const Icon(Icons.add),
      ),
    );
  }
}

📌appBar

The bar across the top — title, back button, actions.

📄body

The main content area of your screen.

➕floatingActionButton

The round button that floats over the content.

⬇️bottomNavigationBar

Tabs or navigation at the bottom.

Widgets: The Building Blocks

Every piece of UI is a widget, and widgets nest inside each other to form a widget tree. The tree below is exactly what the Scaffold above produces:

Widgets come in a few flavors. Here are ones you'll meet constantly:

Stateless vs Stateful Widgets

This is one of the most important concepts. It's all about whether a widget can change over time.

🗿StatelessWidget

Never changes after it's built. Perfect for static things — a label, an icon, a logo. Give it data and it just draws it.

🔄StatefulWidget

Can change and redraw itself. Use it for counters, toggles, forms — anything that reacts to taps or data.

A classic counter shows how state works. When you call setState(), Flutter re-runs build() and updates the screen:

counter.dart
class Counter extends StatefulWidget {
  const Counter({super.key});
  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _count = 0;   // this is our "state"

  void _increment() {
    setState(() {        // tell Flutter: redraw!
      _count++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text('Count: $_count'),
        ElevatedButton(
          onPressed: _increment,
          child: const Text('Add'),
        ),
      ],
    );
  }
}
⚠️

The key idea: You never update the screen directly. You update a variable and call setState(). Flutter figures out what changed and redraws efficiently.

Layout & Styling

Layout in Flutter is done by nesting Row, Column, and Container widgets. You control alignment, spacing, and decoration through their properties.

card.dart
Container(
  padding: const EdgeInsets.all(16),
  decoration: BoxDecoration(
    color: Colors.white,
    borderRadius: BorderRadius.circular(16),
  ),
  child: Row(
    mainAxisAlignment: MainAxisAlignment.spaceBetween,
    children: [
      const Text('Buddy 🐕'),
      const Icon(Icons.favorite),
    ],
  ),
)

↔️Row

Lays children out left-to-right. mainAxisAlignment = horizontal spacing.

↕️Column

Lays children top-to-bottom. crossAxisAlignment = horizontal alignment.

📦Container

Padding, margin, color, rounded corners, shadows — your Swiss-army box.

🫸Expanded

Makes a child fill the leftover space in a Row or Column.

🎁

Pro tip: Wrap any widget in Padding to add breathing room, or SizedBox(height: 12) to add fixed empty space between widgets.

Handling User Interaction

Most widgets that respond to taps expose an onPressed or onTap callback — a function that runs when the user interacts.

buttons.dart
ElevatedButton(
  onPressed: () {
    print('Button tapped!');
  },
  child: const Text('Tap me'),
)

// Wrap ANY widget to make it tappable:
GestureDetector(
  onTap: () => print('The box was tapped'),
  child: const Text('I am clickable'),
)

For text input, you use a TextField together with a TextEditingController to read what the user typed.

Future & async — Calling an API

Real apps fetch data from the internet. That takes time, and we don't want the app to freeze while waiting. Dart handles this with Futures and the async/await keywords.

A Future<T> is a promise: "I'll give you a value of type T… later." It might succeed with data, or fail with an error.

api_service.dart
import 'dart:convert';
import 'package:http/http.dart' as http;

// Returns a Future — the result arrives later.
Future<List> fetchPets() async {
  final url = Uri.parse('https://api.example.com/pets');

  // "await" pauses here until the response comes back,
  // WITHOUT freezing the rest of the app.
  final response = await http.get(url);

  if (response.statusCode == 200) {
    // Turn the JSON text into Dart objects.
    return jsonDecode(response.body) as List;
  } else {
    throw Exception('Failed to load pets');
  }
}

⏳Future<T>

A value that will be available at some point in the future.

🏷️async

Marks a function that does asynchronous work.

⏸️await

Waits for a Future to finish before moving on — without blocking the UI.

🧩jsonDecode

Converts a JSON string into Dart maps and lists.

🛡️

Always handle errors. Networks fail. Wrap awaits in try / catch so your app shows a friendly message instead of crashing.

9

Showing Async Data: FutureBuilder

So how do you put that fetched data on the screen? The FutureBuilder widget listens to a Future and rebuilds the UI for each state: loading, error, and data.

pets_page.dart
FutureBuilder<List>(
  future: fetchPets(),
  builder: (context, snapshot) {
    // 1. Still waiting → show a spinner
    if (snapshot.connectionState == ConnectionState.waiting) {
      return const CircularProgressIndicator();
    }
    // 2. Something went wrong → show the error
    if (snapshot.hasError) {
      return Text('Oops: ${snapshot.error}');
    }
    // 3. Success → use the data
    final pets = snapshot.data!;
    return ListView.builder(
      itemCount: pets.length,
      itemBuilder: (_, i) => ListTile(
        title: Text(pets[i]['name']),
      ),
    );
  },
)
✨

This three-state pattern — loading → error → data — is the heart of every data-driven screen. Master it and you can build almost anything.

Navigation Between Screens

Apps have many screens. Flutter keeps them in a stack — you push a new screen on top and pop to go back.

navigation.dart
// Go to a new screen
Navigator.push(
  context,
  MaterialPageRoute(builder: (_) => const DetailsPage()),
);

// Go back to the previous screen
Navigator.pop(context);
📘

In bigger apps you'll use a dedicated router package like go_router to manage routes, deep links, and URLs cleanly — but the push/pop mental model stays the same.

Bonus: What is Riverpod?

The problem: setState() works for a single widget, but as apps grow you need to share state across many screens — the logged-in user, a shopping cart, fetched pets. Passing data down through dozens of widgets gets painful fast.

Riverpod is a state-management library that solves this. It lets you declare a piece of state (or logic) in one place called a provider, then read it from anywhere in your app — cleanly, safely, and testably.

The core pieces

📦Provider

A container that holds a value or some logic. Defined once, read anywhere.

👀ref.watch

Subscribes a widget to a provider — it rebuilds automatically when the value changes.

🎛️Notifier

Holds state plus methods to change it (like an upgraded, shareable setState).

🧪ConsumerWidget

A widget that can read providers via a ref handle.

A tiny example

Here's the counter from earlier — but now its state lives in a provider and any widget can access it:

counter_provider.dart
// 1. Declare the state in a provider.
final counterProvider = NotifierProvider<CounterNotifier, int>(
  CounterNotifier.new,
);

class CounterNotifier extends Notifier<int> {
  @override
  int build() => 0;          // initial value

  void increment() => state++;  // update = reassign "state"
}
counter_view.dart
class CounterView extends ConsumerWidget {
  const CounterView({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    // Watch the provider — rebuilds when it changes.
    final count = ref.watch(counterProvider);

    return Column(
      children: [
        Text('Count: $count'),
        ElevatedButton(
          // Call a method to change the state.
          onPressed: () => ref.read(counterProvider.notifier).increment(),
          child: const Text('Add'),
        ),
      ],
    );
  }
}

Why people love it

No more setState spaghetti Share state anywhere Easy to test Great for API calls Auto-disposes unused state Compile-safe
🚀

Perfect for APIs: Riverpod has an AsyncValue type that models loading / data / error for you — the same three states as FutureBuilder, but shareable across your whole app. That's why most modern Flutter apps reach for it.
